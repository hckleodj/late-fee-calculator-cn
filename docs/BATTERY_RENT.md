基线：main @ 68a86a6da4aca2aeeff693706e367727eec914b9（2026-09-29 正式产品）。不另找 V2 提交。
本功能已完成隔离开发及自动化/独立浏览器验收，用户于2026-09-30授权发布。未读取正式浏览器客户数据。OPPO N6本轮完整验收范围未单独核实；远端与线上发布结果以发布回执为准。

## 业务与字段

- `plan.amount` 保持合同月租；`principal` 保持历史的合同款（含合同本金和利息）含义。
- 可选 `batteryMonthlyRent`：非负两位小数元；缺失按0读取，不自动补写。
- `batteryRentEffectiveTermIndex`：零基期次；界面显示一基期次。新合同默认第1期，已有无租电合同默认最早未结清期。
- `batteryRentByTerm`：按期保存租电应收金额（元），仅明确保存租电配置时建立。它是历史期间费额的真源；两个设置字段代表最近一次配置。后续改价保留已完整支付期次及生效前期次。
- 为避免历史应计费用漂移，已经有租电费且登记过收款的期次不能直接改价，须选择未登记收款的未来期次。首次给旧合同补租电费允许选尚未结清的部分付款期，保留原合同款分配。禁止改已完成历史期。
- 有流水的合同禁止直接修改已知车价/首付/月利率/贷款额，以及月租/日费率/日期/期数；缺失金融资料可在原月供及全部已知口径不变时补齐。修改完成期数须通过收款或撤销，没有覆盖或重算旧流水的隐式路径。

## 收款

新收款 `allocationVersion: 2`，包含 total / principal / batteryRent / lateFee / date / startTermIndex / allocations。
每个 allocation 包含 termIndex / principal，按需增加 batteryRent / lateFee（零值可省略）。均以元存储，以整数分分配，严格核对各组成与总额守恒。
同一期先合同款、再租电费、再剩余滞纳金，最后进入下一期。收款界面仅输入实际到账总额和日期，自动从最早待处理期抵扣。基础款全额付清后可单独减免滞纳金；减免不计入实收。细则见 AUTO_PAYMENT_LATE_FEE.md。未来日期禁止登记。

示例：3142.88 + 728 = 3870.88；收3500 => principal 3142.88，batteryRent 357.12，余租电费370.88，completedTerms不增加。

新增、修改及撤销只影响指定流水；其他历史 allocations 不清空、不重放。撤销后欠款恢复，但后续流水保留原期次归属，不自动前移。修改为更早付款日如导致后续已收滞纳金超过应计，将拒绝保存。

## 滞纳金与完成期数

按本地业务日期转UTC日序，不按毫秒时长计算。应付日不收费；付款当天仍按付款前余额收费，次日起降基数；到期前付款先减基数。同一天多笔付款合并产生相同结果。
按付款日期排序：每段未付基础款（合同款+租电费）×天数×日费率，各段合计后每期四舍五入到分（BigInt十进制比率，避免逐段舍入造成多收）。后续付款不抹除之前已产生的费用。

- accruedLateFee：累计应计
- paidLateFee：登记已收
- waivedLateFee：有效减免
- remainingLateFee：max(0,应计-已收-有效减免)
- lateFeeCredit：历史超收待核对；不自动抵基础款

5天×3870.88×0.005 + 3天×370.88×0.005 = 102.3352 => 102.34元。
completedTerms只看连续各期合同款和租电费是否结清。独立待处理提醒扫描全部期次，基础款已清但有未收滞纳金的期次仍保留。
新的分段规则同时修正普通合同部分付款后的历史计费；普通无部分收款/无已收滞纳金时保留原催款格式，不展示租电费0元。独立滞纳金计算器公式不变。

## 历史费用兼容与限制

旧流水没有逐期滞纳金分配，不能声称知道当年真实期次归属。只读视图按收款日、起始期、最早未抵费用顺序推导，余量挂起始期作为历史超收待核对。界面明确提示需对照原始凭证。
首次对该合同执行租电配置或收款变更时，在 plan.legacyLateFeeAllocations 中保存这一派生映射，旧 payment/allocations 不修改；后续不随新增付款而漂移。这是受保存授权的增量字段，不是读页面时自动迁移。
历史原始收款日期缺失/非法时，保留数据及备份能力，显示待核对提示并停止该合同的分段催款/收款计算，不猜测日期。旧版只有完成期数而没有流水的 openingCompletedTerms 继续视为历史基础款完成；不虚构其付款日期或历史滞纳金。

## 结清与测算

结清只从合同款拆本金/利息，租电费完全独立。到期未付租电费另列，未来租电费不擅自视为提前结清债务。
方案计算新增 batteryMonthlyCents；原固定月租、车辆金额、预付/押金、合同利息及尾差完全不变。
paymentSchedule 原 dueCents 不变，新增 batteryRentCents / comprehensiveDueCents；后者=抵扣后租金+租电费。摘要、表格、客户文字、PNG、PDF共用同一结果。方案测算租电费从第1期生效；合同台账可选生效期，两者原本就是独立模块，没有新增自动建合同功能。

## 数据安全

不改正式key，不初始化正式主数据、不批量回写旧客户。所有业务保存继续调用 savePlans → revision/dirty/hash/snapshot。完整JSON序列化保留新增字段，旧JSON仍可恢复；新字段校验和逐笔金额守恒纳入备份/快照恢复。
新页面缺少账单模块时校验失败进入保护，不能回退到忽略租电费的计算。模块资源使用内容hash版本，避免旧缓存混用。
旧生产代码不识别新增字段，写入新数据后不能直接回滚旧页面继续经营；正式发布审查须准备含新字段的备份和数据兼容回滚方案。
