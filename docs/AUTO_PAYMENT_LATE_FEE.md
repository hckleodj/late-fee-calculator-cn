# 自动收款抵扣与滞纳金减免（隔离候选）

开发基线：8f16bf5b518d31bc0ee671d40ae498afe608cf80。
发布前生产基线为68a86a6；用户于2026-09-30明确授权部署，本次不访问真实客户数据。

## 已确认规则

- 收款只填写实际日期和到账总额，不再选择是否包含滞纳金。
- 从最早待处理期自动抵扣：合同月租 → 当期租电费 → 当期剩余滞纳金 → 下一期。选择后续期也不能跳过前期待收费用。
- 滞纳金按收款日期计算，基础款仍按原有实际未付款分段计费；付款日旧余额、次日新余额，公式不变。
- completedTerms仍表示连续基础款完成期数。基础款已清、滞纳金未处理的期次继续提醒。
- 滞纳金调整入口仅支持减免，基础款未全额付清时禁止减免。
- 剩余滞纳金=max(0,应计－已收－有效减免)。减免不计入实收，不抵基础款，不进入融资本金或合同利息。

## 数据与历史

新增可选plan.lateFeeWaivers数组，每条包含id、termIndex（零基）、amount（元）、reason、date（本地业务日）。撤销追加reversedAt，不删除原始记录。缺失数组按无减免读取。

新收款仍使用allocationVersion:2，合同款principal历史语义不变，分币计算且总额守恒。历史流水、分配不自动重放；明确编辑一笔流水时，该笔按新自动顺序重新分配，保存前显示明细，其他流水保持原样。

减免金额不得超过当日剩余滞纳金，原因必填。新增减免和撤销走现有revision、dirty、hash、snapshot及完整JSON备份。备份恢复校验减免字段及与基础款的关系。已减免期若需撤销/修改依赖的基础款收款，必须先撤销减免，防止账目矛盾。

旧版代码不能理解新减免数据，不能换回旧页面继续收款。生产发布前仍须做含新增字段的备份并准备兼容回退方案。

## 验收

自动化覆盖：自动抵扣、跨期、不能跳过前期费用、部分/全额付款、全额/部分减免、余额上限、未清基础款禁止减免、撤销留痕、阻止破坏减免依赖的收款编辑、旧流水保留、旧字段缺失、备份字段校验、revision/hash/snapshot、提醒移除。

OPPO N6隔离验收：
1. 仅导入虚构客户，先确认JSON已保存。
2. 应收合同3142.88、租电728时收3500：合同全清、租电付357.12、余370.88，不能减免。
3. 补370.88后基础款完成；剩余滞纳金仍在提醒。
4. 打开滞纳金调整，填剩余金额及原因，保存后本期待处理移除；实收金额不变。

6. 一笔收款超过本期基础款时，核对先抵本期滞纳金，再抵下一期合同款。
7. 使用后进入发布审查，不直接部署。
